ZMQ-in / UDP-out Simulator#

A Python simulator for the GeRM (Germanium Readout Module) detector developed at NSLS-II. It accepts device configuration and acquisition control commands over ZMQ REP and emits simulated detector event data as UDP datagrams in the real GeRM wire format.

An EPICS AreaDetector IOC (ADGerm) bridges the detector (real or simulated) to the EPICS control system, and a Phoebus screen provides a graphical operator interface.

Prerequisites#

  • macOS arm64 (Apple Silicon) — the IOC and Phoebus distribution are arm64 builds

  • pixi — manages all Python + EPICS + Java dependencies

  • Xcode Command Line Tools — required to build the IOC C++ driver

    xcode-select --install

  • IOC compiled — see Building the IOC below

Full system startup#

Open three terminals in the repo root, each running one piece.

Terminal 1 — Simulator#

pixi run simulate

The simulator binds a ZMQ REP socket on tcp://*:5556 and listens for commands. It will start sending UDP frames to port 9870 once the IOC triggers an acquisition.

Terminal 2 — EPICS IOC#

pixi run ioc

Starts the germIOC binary, loads all PVs, and drops you at the epics> prompt. On a clean start you should see iocRun: All initialization complete and no ERROR lines.

Useful IOC shell commands:

epics> dbl                           # list all ~1063 PVs
epics> dbpr "GERM:cam1:Acquire" 1    # print record with fields
epics> dbgf "GERM:cam1:DetectorState_RBV"

Terminal 3 — Phoebus GUI#

pixi run phoebus

Opens the ADGerm.bob screen pre-loaded with macros P=GERM: and R=cam1:. Phoebus takes ~10 s to start on first launch.

Tip: Phoebus connects to the IOC over Channel Access. Both must run on the same host (or set EPICS_CA_ADDR_LIST appropriately).

Running an acquisition#

Via the Phoebus GUI#

  1. In the Acquisition section set Image Mode (Single / Multiple / Continuous) and Num Images.

  2. Click Acquire — the button turns green and Detector State shows Acquiring.

  3. To save to HDF5 (Stream mode — all frames in one file, default):

    • IOC startup defaults: FilePath=/tmp/, FileName=germ, FileTemplate=%s%s%4.4d.h5, FileWriteMode=Stream, NumCapture=0 (unlimited), AutoIncrement=Yes

    • Workflow (Stream mode requires at least one array before Capture=1):

      1. Acquire once with Capture=0 (warms up the HDF1 plugin)

      2. Set Capture=1 → file opens (e.g. /tmp/germ0001.h5)

      3. Acquire data — frames stream into the file

      4. Set Capture=0 → file closes

    • Set Num Frames to limit frames per file (0 = unlimited stream until Capture=0)

Via the IOC shell (epics>)#

HDF5 file saving (Stream mode)#

Default: FileWriteMode=Stream, NumCapture=0 (unlimited), AutoIncrement=Yes. All frames in one file; requires one warmup acquisition first.

# 1. Warmup (sets internal NDArray dims, no file written if Capture=0):
dbpf "GERM:cam1:NumImages"     "1"
dbpf "GERM:cam1:ImageMode"     "Single"
dbpf "GERM:cam1:Acquire"       "1"

# 2. Stream N frames into one HDF5 file:
dbpf "GERM:HDF1:NumCapture"    "100"    # 0 = unlimited
dbpf "GERM:HDF1:Capture"       "1"      # open file
dbpf "GERM:cam1:NumImages"     "100"
dbpf "GERM:cam1:ImageMode"     "Multiple"
dbpf "GERM:cam1:Acquire"       "1"      # stream data
# Capture=0 or NumCapture reached → file closes automatically

# Stop early:
dbpf "GERM:HDF1:Capture"       "0"
dbpf "GERM:cam1:Acquire"       "0"

Building the IOC (first time)#

The EPICS IOC is not pre-built in the repo — you must compile it once after cloning. All steps assume macOS arm64 with pixi installed.

# 1. Install pixi env (Python + EPICS base + Java + ZMQ + HDF5 …)
pixi install

# 2. Clone and build support modules (one-time, ~10 min)
mkdir -p epics-support && cd epics-support

#  asyn
git clone --depth=1 -b R4-44-2 https://github.com/epics-modules/asyn.git
#  busy
git clone --depth=1 https://github.com/epics-modules/busy.git
#  calc (provides sseq record used by NDStats)
git clone --depth=1 https://github.com/epics-modules/calc.git
#  ADSupport
git clone --depth=1 https://github.com/areaDetector/ADSupport.git
#  ADCore
git clone --depth=1 https://github.com/areaDetector/ADCore.git

# 3. Create CONFIG_SITE.local for each module (overrides conda-forge cross-compiler)
#    See ADGerm/configure/CONFIG_SITE for the required content.

# 4. Build each module in order:
#    asyn → busy → calc → ADSupport → ADCore

# 5. Build the ADGerm driver
cd ../ADGerm && make -j4

macOS build note: The conda-forge epics-base package sets CC to a cross-compiler that does not exist at runtime. Each module’s configure/CONFIG_SITE.local must override CC, CXX, and CCC to point to the Xcode clang/clang++ and set CONDA_BUILD_SYSROOT + MACOSX_DEPLOYMENT_TARGET=11.0.

# Terminal 1 — start the simulator
pixi run simulate

pixi run test

ZMQ command reference#

The simulator binds a ZMQ REP socket (default tcp://*:5556). Clients connect with a ZMQ REQ socket and exchange JSON messages.

configure#

Set device parameters. Must be sent before start_acquisition.

{
  "command": "configure",
  "params": {
    "exposure_time":    0.1,
    "num_frames":       10,
    "events_per_frame": 10
  }
}

Parameter

Type

Default

Description

exposure_time

float

0.1

Seconds between frames

num_frames

int

10

Total frames to acquire

events_per_frame

int

10

Simulated detector events per frame

start_acquisition#

Begin emitting UDP data. Device must be in READY state (i.e. configure was sent).

{"command": "start_acquisition"}

stop_acquisition#

Abort an in-progress acquisition.

{"command": "stop_acquisition"}

status#

Query current state and configuration.

{"command": "status"}

Example reply:

{
  "status": "ok",
  "state":  "ACQUIRING",
  "config": {
    "exposure_time":    0.05,
    "num_frames":       10,
    "events_per_frame": 20
  },
  "frames_sent": 3
}

Reply envelope#

Every command returns a JSON object with a "status" field:

Value

Meaning

"ok"

Command accepted

"error"

Command rejected; see "message" field

UDP packet format#

The simulator emits data on the configured UDP port (default 9870) using the GeRM detector wire protocol defined in NSLS2/germ_agent, specifically:

  • Packet framing: germ_agentApp/data_write.c

  • Packet constants and buffer structures: germ_agentApp/germ.h

  • UDP socket handling: germ_agentApp/udp_conn.c

  • Event word bit layout: zDDMApp/src/devzDDM.c

All packet header fields are big-endian (network byte order). Each frame is transmitted as a sequence of UDP packets delimited by SOF and EOF markers.

Event payload#

Each event occupies two consecutive 32-bit words (8 bytes).

Word 0 — hit descriptor:

Bits

Width

Field

Description

[30:27]

4

chipnum

ASIC index (0–11)

[26:22]

5

channel

Channel within ASIC (0–31)

[21:12]

10

td

Timing data (ToA or ToT depending on ASIC mode)

[11:0]

12

pd

Pulse-height / energy ADC value (0–4095)

Word 1 — timestamp:

Bits

Width

Field

Description

[28:0]

Derived pixel index: pixel = 32 × chipnum + channel (max 384 pixels across 12 ASICs × 32 channels).
